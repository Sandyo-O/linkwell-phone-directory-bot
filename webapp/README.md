# 分機查詢 - 純前端版(跟Dify版本並存)

這是跟 `voice/`(Dify + 本機語音伺服器版本)完全獨立的另一套實作,兩邊互不影響、也不共用程式碼(只有 `build-data.js` 會讀取 `voice/directory.json` 來產生資料)。

## 這個版本解決什麼問題

Dify版本的核心限制是:不管是查分機還是用語音,都要有一台電腦開著跑Docker+Dify+語音伺服器,只要那台電腦關機,所有人都查不到。

這個版本把「查詢比對」「語音辨識」「語音朗讀」全部搬進**瀏覽器裡直接執行**,不需要任何伺服器：

- 分機資料庫(1323筆)直接包進網頁裡,姓名比對、拼音模糊比對都在瀏覽器算
- 語音辨識用 Whisper(透過 `@huggingface/transformers`,在瀏覽器裡用WebAssembly執行,第一次使用要下載模型,約100多MB,之後瀏覽器會快取)
- 語音朗讀用瀏覽器內建的朗讀功能(不同瀏覽器/系統音色不同,沒有辦法像Piper一樣客製化調整斷句)

所以只要把 `index.html`、`data.js` 這兩個檔案放到任何一個網頁空間,同事用自己的手機或電腦打開,就能查,完全不需要您的電腦開著。

**目前部署在 Cloudflare Pages**(接 GitHub repo 自動部署,推到 `master` 就會自動重新發布):`https://linkwell-phone-directory-bot.pages.dev`

## 密碼關卡

因為沒有申請 Cloudflare Access(需要信用卡驗證),改成在網頁本身加一道簡單的共用密碼(目前是 `syscom`,要改的話在 `index.html` 裡搜尋 `GATE_PASSWORD_HASH`,換成新密碼的SHA-256雜湊值)。

**這不是真正的存取控制**,只是擋掉不小心點到連結、或搜尋引擎爬到的情況——網頁原始碼本身是公開的,懂技術的人一樣能繞過去查看`data.js`裡的完整資料。如果之後能接受Cloudflare Access的信用卡驗證,或申請到公司內部網域憑證,應該換成真正的存取控制而不是只靠這道密碼。

## 重要取捨(上線前務必知道)

1. **整份通訊錄資料會在網頁原始碼裡**:任何打開這個網頁的人,用瀏覽器「檢視原始碼」或看network請求,就能看到 `data.js` 裡全部1323筆姓名/分機/部門資料,密碼關卡擋不住這件事,只是擋掉隨手點進來的人。如果通訊錄外洩到公司以外的人手上是您不能接受的風險,不要把連結分享到公司以外。
2. **寄email用`mailto:`連結**,不是自動寄出:點了連結會打開使用者自己的Outlook/Gmail App,信件內容已經幫忙填好,使用者自己按送出。這是因為純前端沒有安全的地方放Resend/SendGrid的API金鑰(放在網頁裡任何人都看得到,會被拿去亂寄信)。
3. **語音辨識/朗讀的品質跟Dify版本不同**:語音辨識一樣是Whisper,但跑在瀏覽器WebAssembly裡通常比本機Node.js執行慢一些;語音朗讀改用各瀏覽器/系統內建的語音,不是Piper,音色和斷句效果會不一樣,而且不同手機/電腦聽起來可能不一樣。

## 怎麼用

### 本機測試

```bash
cd webapp
python -m http.server 8080
# 或用任何其他靜態伺服器工具
```

打開 `http://localhost:8080`。

### 之後要更新分機資料

分機資料庫更新後,重新產生 `data.js`:

```bash
cd webapp
node build-data.js
```

會讀取 `../voice/directory.json`(跟Dify版本用同一份資料來源),重新輸出 `data.js`。

### 正式部署

把 `index.html`、`data.js` 兩個檔案放到你們公司內部的網頁空間即可,不需要任何後端、資料庫、Node.js執行環境。**請確認這個網頁空間至少要有登入機制,或不對公司外開放**,原因見上面「重要取捨」第1點。
